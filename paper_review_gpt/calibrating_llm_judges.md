# Calibrating LLM Judges：给裁判的判断配一个可信的置信度

> 原文：Bhaktipriya Radharapu 等，[Calibrating LLM Judges: Linear Probes for Fast and Reliable Uncertainty Estimation](https://arxiv.org/pdf/2512.22245v1)，2025-12-23，v1。本文为中文技术解读；核对日期：2026-09-27。

这篇给已经完成评判的 LLM 加一个小型线性 probe，估计“刚才这次判断有多大概率符合标准标签”。核心是**冻结 judge、读取内部表示、训练置信度预测器**。

**1. 场景：LLM 在给已有回答当裁判**

输入是“问题 + 回答 A + 回答 B”。Judge 比较两份回答，输出推理与判决；probe 再输出这次判决的可靠程度。候选回答事先已存在，本文不训练生成它们的模型。

Judge 的输出有三种：Llama 直接选 A/B；Qwen 分别打分、取高分者；GPT-OSS 给出从“A 明显更好”到“B 明显更好”的五档比较。实验也用已有的 **J1**：这是先前工作通过 RL 训练的专用裁判，本篇只给它加 probe。[§3；[J1 原文](https://arxiv.org/abs/2505.10320)]

**2. 问题：裁判报出的把握，不一定可信**

教学例子：100 次判断都报 90% 把握，最终只有 60 次符合标准标签，就过度自信了 30 个百分点。系统若只看“90%”，会放行许多错误判断。

另一办法是让 judge 独立评判十次，看投票是否一致，但每次都要生成推理。本文希望用一次评判得到较可信的 confidence。

**3. 方法：生成完整评判，再读取一个向量**

训练流程如下。[§3、附录 A.5–A.6]

1. 冻结 judge，输入问题和 A/B。Prompt 要求比较、说明不确定之处、给出判决，并报告文字形式的置信度。
2. 从生成序列的 **last token** 提取某层 residual-stream hidden state，记为 $h\in\mathbb R^d$。
3. 用判决与数据集 winner 是否一致，构造 $y\in\{0,1\}$。这里只知道“这次判对/判错”，**没有人工标出的 0.8、0.9 置信度真值**。
4. 只训练一个 $d\rightarrow1$ 的线性层，以 Brier/MSE 损失拟合 $y$；输出截到 $[0,1]$ 作为置信度。附录描述的是线性回归加截断，不能自行替换成 sigmoid 分类器。

推理时执行同样的“生成 → 取向量 → probe”，无需标准标签。层数由验证表现选择：8B/32B 和 Scout 用第 16 层，70B 用第 32 层，GPT-OSS-20B 用第 8 层。验证集具体规模未说明。

**“Fast”仍然要等 judge 写完推理。** 相对十次采样，主要节省的是九次完整生成；约 10× 是这种比较下的推理开销优势，不能理解成单次 forward 就完成整段评判，或已证明端到端延迟必降十倍。

原文只写 last token，未明确 EOS、结束标签的处理，不能断言取的是 A/B 字母本身。访问 hidden state 是必要条件，只有文本输出的封闭 API 无法直接套用。

**4. 训练数据：4,000 条评判记录，标签由 judge 的表现产生**

| 来源 | 内容与监督依据 | 实际抽取量 |
|---|---|---:|
| PPE Correctness | MMLU-Pro、MATH、GPQA、MBPP-Plus、IFEval 的候选回答；用标准答案或可执行检查确定正确回答 | 合计 2,000 |
| PPE Preference | Chatbot Arena 的问题、两份回答及人类偏好 winner | 2,000 |

原始数据由 PPE 提供；本文让各 judge 运行后，构造自己的 **`(hidden_state, 判决是否符合 winner)`** 训练记录。偏好任务的 $y=1$ 表示符合记录中的人类选择，不等于客观真理，也不是人类投票比例。[§3、A.5；[PPE 官方说明](https://github.com/lmarena/PPE#benchmarks)]

训练 10 epochs，batch size 4，学习率 $10^{-4}$，weight decay 0.01；报告三次不同划分的平均结果。论文称剩余约 10K 条用于同分布测试，但正文所列 10.2K + 12.7K 与“4K 训练 + 约 10K 测试”对不上，筛选细节未说明。上述 4K 也不能理解成 4K 个独立原始问题。

**5. 实验：置信度更准，但并非所有数据上都赢**

同分布测试用留出的 PPE；分布外用 JudgeBench（620 对，考正确/错误回答比较）和 RewardBench（约 3K 对，涉及聊天、偏好、安全和推理等）。测试覆盖 Llama/Qwen 及其 J1 版本，另有 Scout、GPT-OSS。[§3]

主要 baseline：直接读模型自报的 confidence；重复采样计算一致率；多数投票并用多数占比作 confidence。后两者主设置为 10 次采样、温度 0.7。[§3、A.9–A.10]

**两个指标都越低越好，但不直接测 judge 准确率：**

- **ECE**：按置信度分桶，求每桶“平均把握与实际正确率之差”的绝对值，再按人数加权。本文桶宽 0.1；上面的 100 条若都在同一桶，ECE 就是 $|0.9-0.6|=0.3$。
- **Kuiper**：将置信度 $S_j$ 从小到大排序，累计真实结果 $R_j$ 与预测的差，再取累计曲线的最高点减最低点。本文特别采用权重 $W_j=S_j$：

$$
C_k=\frac1n\sum_{j=1}^k(R_j-S_j)S_j,\quad C_0=0,\qquad K=\max_k C_k-\min_k C_k.
$$

教学演算：两条样本 $(S,R)=(0.4,1),(0.8,0)$，累计值为 $0,0.12,-0.20$，所以 $K=0.32$。权重使高置信度样本的误差影响更大；这不是不加权版本。[§3]

以下为 **Qwen 32B prompted judge**，每格是 Kuiper / ECE：[Table 1–2]

| 测试集 | 自报 confidence | 多数投票 | Probe |
|---|---:|---:|---:|
| PPE Correctness | .107 / .108 | .125 / .137 | **.020 / .028** |
| PPE Preference | .196 / .194 | **.038 / .065** | .066 / .077 |
| JudgeBench | .103 / .107 | .159 / .198 | **.055 / .059** |
| RewardBench | **.023 / .027** | .034 / .035 | .092 / .106 |

可见它在正确性判断和 JudgeBench 上有效；Preference 上未全面胜过投票，RewardBench 上反而明显变差。作者认为后者较容易，probe 低估把握；这是作者对结果的解释。[§4]

校准好也不保证能挑出哪条会错。例如所有样本统一报总体正确率，可能校准不错却无法排序。论文另用 AUROC、置信度阈值下的准确率检验筛选能力；部署仍需看保留多少样本。[A.1–A.2]

**6. 一条真实样本走全过程**

来自 [PPE Preference](https://huggingface.co/datasets/lmarena-ai/PPE-Human-Preference-V1)，ID：`3c25f48f5dd74458883e244a50025324`。以下是原始问答的节选、转述；**judge 输出和 probe 数值均为教学构造，不是论文运行记录**。

```python
a = [4, 5, 6]
b = a[:]
a[1] = 0
print(b)
```

问题是代码输出什么。A、B 都给出 `[4, 5, 6]`，但 A 的解释中又声称修改 a 会影响 b，前后矛盾；B 解释此次赋值只修改 a。数据集的人类 winner 是 **B**。

将问题和两份完整回答填入 PaV 模板，关键要求可转述为：“比较回答质量，说明理由和不确定之处，输出 A/B 及 0–100 置信度。”[A.12]

假设 Llama judge 输出：

```text
<think>A 的解释前后矛盾；B 对这次列表赋值的解释更准确。</think>
<answer>[[B]]</answer>
<confidence>90</confidence>
```

自报方法直接取 **0.90**。Probe 方法读取生成序列末端所选层的向量 $h$，假设算出 **0.76**：它估计这次“选 B”的判断符合标签的概率。由于 winner=B，训练监督为 **1**，此时平方误差为 $(0.76-1)^2=0.0576$；若 judge 选 A，监督就是 0。

90 是模型自己说的数，0.76 是 probe 的估计，1 是通过 winner 算出的监督：三者职责不同。

**7. Takeaway**

- 实质贡献是用已有 judge 的内部表示训练一个廉价的置信度模块；确实有参数训练，但不更新 LLM 本体。
- 最有支持的结论是：一次完整评判后的表示能提供有用的校准信号，省去反复采样；分布外收益有明显边界。
- 可借鉴的是“收集本领域判决对错 → 训练 probe → 检查校准和筛选覆盖率”。换 judge、prompt 或任务后需要重新验证，本文没有证明一个 probe 能通吃。
