# Harness-Zero：把外部 harness 的工作流程教进模型

> **发表状态（核对日期：2026-09-29）：** [arXiv 预印本](https://arxiv.org/abs/2609.24974)。

- 论文：[Harness-Zero: Harness Distillation via Agent-as-Harness](https://arxiv.org/abs/2609.24974)，阅读版本 v1。
- 作者：Haoran Ye、Yuxing Lu、Haonan Dong、Zhaochen Su、Guojie Song。
- [原文及附录](https://arxiv.org/html/2609.24974v1) · [官方代码](https://github.com/metaevo-ai/harness-zero)
- 整理日期：2026-09-29。下文的教学例子与论文实际实验结果明确区分。

**这篇想解决的问题：一个 agent 靠外部 harness 才能做好的事情，能不能通过训练，让模型自己也会做？** 作者让 reviewer 在学生执行动作前进行纠正，再用接受后的轨迹训练学生。部署时移除 reviewer 和领域 harness，保留最小的执行环境。

## 1. 场景：模型与外部系统分别做了什么

实验覆盖修改 Excel、跨应用操作和化学逆合成（根据产物预测反应物）。

| 对象 | 职责 |
|---|---|
| 学生 Qwen3.5-9B | 读任务、生成推理和下一步操作 |
| 最小 harness `h` | 固定提示词、一个 Bash execute 工具、返回执行结果 |
| 领域 harness `h*` | 专用工具、检查中间件、skills、失败经验 |
| Reviewer / harnessing agent | 参考私有材料 `K`，审核并纠正学生提议 |
| 参考材料 `K` | 从 `h*` 改写而来，说明何时介入、怎样构造学生能执行的操作 |

“只有 Bash”仍可运行 Python、调用环境里的库和操作文件。附录 E.1 还提供通过 Bash 调用的单层子 agent 委派入口，实际使用较少。因此，Harness-Zero 并非完全去掉 harness。

## 2. Motivation：系统会检查，不代表模型学会检查

假设学生修改 Excel 后直接说“完成了”，从不检查有没有覆盖原有示例。

在 harness 里加上“提交前检查，发现错误就拦住”的规则，可以提高系统成功率；但检查一直由外部代码完成，拿掉它，模型可能仍然直接提交。

作者希望把这些有效流程变成训练信号，让模型主动执行检查。这样，不同领域积累的工作流程有机会进入模型参数，减少部署时对各自复杂 harness 的依赖。（§1）

**为什么不直接拿好 harness 的成功轨迹做 SFT？** 有两个障碍：

- **动作不兼容：** 教师调用了专用工具，学生部署时只有 Bash，模仿后可能调用不存在的工具。
- **关键操作在后台：** harness 自动检查后只告诉模型“B3 错了”；模型可以学会收到提醒后修复，却没有学会自己发起检查。

因此，关键是把外部能力转成学生在部署环境中能够独立完成的行为示范。

## 3. 方法：每一步执行前审核，结合已有整条轨迹判断

方法分三阶段。（§3；附录 A–C）

**先构造领域 harness。** 用 Kimi K3 分析训练任务上的失败，迭代三轮，更新共享工具、规则、skills 和经验。再改写为 reviewer 私有参考材料 K。例如，原来的自动提交检查，改成“若当前准备结束且历史没有检查证据，则要求补一次检查”。

**再采集纠正后的轨迹。** 学生使用最小 harness，GPT-5.6 Sol 担任 reviewer。每轮：

1. 学生提出下一条响应，暂不执行。
2. Reviewer 读取任务、截至当前的学生轨迹、当前提议和 K。
3. 选择 PASS（原样放行）或 REPLACE（提供完整替代响应）。
4. 通过学生的 execute 工具执行接受的动作；结果进入学生上下文。
5. 学生依据新结果继续下一轮。

**审核单位是当前 step；判断依据是当前 trajectory prefix。** 它不会等全部结束后才统一评分。这里的 step 指一条响应或工具调用，不是逐个检查每个 reasoning token。最终回答也属于审核对象；缺乏验证时，可以把“完成了”替换成检查动作。

Reviewer 不能私下查看学生沙箱、标准答案或隐藏 verifier 反馈。需要新证据时，必须把获取证据写成学生能执行的动作。每步都会审核，但不一定替换；替换次数有预算。

**最后训练学生。** 对所有接受的响应做 LoRA SFT，包括未修改的学生响应和替换响应。被拒绝的草稿与私下审核意见不进入学生轨迹；意外混入的 reviewer 视角推理会被 mask。更新学生的 LoRA 参数，不训练 reviewer；部署只保留训练后的学生和 h。

## 4. 训练数据：任务数、轨迹数与筛选方式

| 数据 | 训练任务 | 保留轨迹 | 测试任务 | 轨迹筛选 |
|---|---:|---:|---:|---|
| SpreadsheetBench Verified | 300 | 487 | 100 | verifier reward=1 且无执行异常 |
| AppWorld | 147 | 282 | 168，组成56个场景 | 同上 |
| USPTO Retrosynthesis | 500 | 500 | 100 | 保留全部采集轨迹，包括失败 |

任务可以重复采集，所以轨迹数不等于独立题目数。三组均检查私有审核信息泄漏。**Reviewer 在线不能看隐藏 verifier 反馈，与采集结束后用 verifier 筛选轨迹，是两个阶段。**

一条监督记录可理解为：

`任务 + 已接受动作 + 环境结果 → 下一条接受的学生式响应`

监督目标来自学生与 reviewer 共同产生的响应，不是一个额外的逐步正确性标签。LoRA rank=32，训练两轮。**三个领域分别训练各自模型，44.3%的宏平均不是同一个混合训练模型跨领域的结果。**（§4.1；附录 D、E.3）

## 5. 实验：学进了多少，哪些还没学进去

主要结果来自 Table 2，单位为百分比。

| 配置 | 表格 | AppWorld | 化学 | 宏平均 |
|---|---:|---:|---:|---:|
| 原始学生 + h | 31.0 | 26.8 | 12.0 | 23.3 |
| 原始学生 + h* | 39.0 | 48.2 | **38.0** | 41.7 |
| Harness-Zero + h | **44.0** | **58.9** | 30.0 | **44.3** |

表格、化学使用单次任务成功率 pass@1；AppWorld 使用场景目标完成率 SGC。宏平均是三项等权平均。化学任务仍落后于保留专用 harness 的配置，说明流程与领域知识并未全部内化。

Table 3 **只在化学任务上**比较数据来源：

| 训练轨迹来源 | 采集成功率 | SFT后测试成功率 |
|---|---:|---:|
| 强教师直接生成 | 52.0 | 12.0 |
| Reviewer 可读标准答案 | 98.6 | 15.0 |
| Harness-Zero 的领域参考指导 | 59.4 | 30.0 |

所以截图中的12%、15%应与30%比较，不能与跨领域宏平均44.3%比较。给出正确答案能帮助采到成功轨迹，却未必教会可泛化的操作过程；这些结果也不能推出“教师蒸馏普遍无效”。

Table 4 另报告28类行为平均恢复率82.3%。这是在“基座有 harness 才出现该行为”的筛选任务上计算的行为恢复，不是准确率，也不保证每次执行该行为都正确。

## 6. 一条样本走全过程：从被提醒修复到主动检查

以下依据附录 B.2 的保护预填单元格机制构造教学示例；具体单元格与运行输出为演示，不是公开实跑记录。

**任务：** 按已有示例填充 Excel 空白，保留原有内容。

Reviewer 的关键要求可以简化为：“审核下一步；如果提交前缺少输入输出对照证据，就用学生可执行的检查替换提交。”

| 阶段 | 发生什么 |
|---|---|
| 学生已经执行 | 读取文件、推断规则、填写并保存 |
| 学生当前提议 | “完成了。” |
| Reviewer 判断 | 历史没有证明原有示例未被覆盖 |
| REPLACE | 学生式推理：“我需要检查已有内容是否改变。”并通过 Bash 执行 Python 比较脚本 |
| 环境返回 | `FAIL changed cells: ['B3']` |
| 学生继续 | 根据可见结果修复 B3，再检查并提交 |

SFT 学习的是“主动检查—读取结果—修复”的过程。Reviewer 的私下理由不作为学生回答。部署时，希望学生无需 reviewer 提醒，也会生成类似验证动作。

## 7. Takeaway：它与 confidence / verification 的关系

- **贡献在于可学习的行为转换。** 将外部规则落实为学生当前状态下、部署接口内可执行的下一步，再用轨迹训练。
- **它有执行前 review 和验证动作，但没有保证逐步正确。** Reviewer 可以识别缺失检查、重复错误和过早提交，也可能判断失误；它不输出经过校准的最终答案正确概率，论文没有做基于该概率的拒答评估。
- **成本与适用边界：** 每步额外审核增加采集成本，USPTO平均时延约为最小 harness 的2.4倍；这项审核开销在蒸馏后移除。方法依赖强 reviewer，部分领域知识和后台机制难以完整内化。（§5；附录 F）

对 trajectory confidence 研究的启发（本文解读，非作者已验证结论）：可以借鉴“检查依据必须来自可见轨迹、缺证据就显式获取”的设计。但把 PASS/REPLACE 当作正确性标签或置信度，需要另做验证；是否值得介入，并不等于最终答案是否正确。
