# DeonticBench：模型能否把给定规则用对？

论文：[DeonticBench: A Benchmark for Reasoning over Rules](https://arxiv.org/abs/2604.04443v1)，Guangyao Dou 等，2026-04-06，arXiv 预印本。本文依据 v1 正文、附录及下列固定版本官方代码撰写。

**核心结论：**这篇构建了包含 6,232 道题的规则推理基准，并比较直接回答、生成 Prolog 和模型后训练。程序能运行，不代表它翻译对了规则；符号执行的收益明显依赖任务和提示方式。

**1. 场景**

给模型一份税法、行李政策、住房法规或移民裁决规则，再给个案和问题，让它算金额或判断结论。考点是使用题目提供的规则；SARA 与 Airline 共享领域规则，Housing 与 USCIS 的规则随个案变化。（§2、§2.6）

**2. 想解决的问题**

官方样本 `s1_a_2_ii_neg`：Alice 具有 surviving spouse（遗属配偶）身份，应税收入 95,129 美元；待判断的陈述是“按 §1(a)(ii) 缴税 22,018 美元”。这个金额看似合理，但 ii 档只覆盖收入大于 36,900、至多 89,150 的情况，因此标签是 **Contradiction**。只核对金额、忽略条款适用范围，就会答错。这是依据真实样本构造的错误示例，不是论文披露的模型输出。[2]

这类题同时要求选规则、处理条件和例外、绑定人物与年份、完成计算。算术工具只能解决其中一环。

**3. 方法**

测试比较三条路径：Direct 直接输出答案；Zero-shot 把规则和事实写成完整 Prolog；Few-shot 多给参考示例，再生成新程序。后两者由 SWI-Prolog 执行并输出金额或标签。即使提供示例，待测模型仍须为新个案生成相关规则与事实，并非调用一套固定、已验证的规则库。（§3.1）

另一个流程是**制作参考程序**：o3 生成代码，只有执行成功且答案符合 gold（标准答案）才保留；初始样本经人工抽查、修订，再用于后续生成。失败时可带上旧代码和执行报错重试，每题至多生成两次（首次＋一次重试）。这是数据构造流程，不能当作测试时 agent 自动修复能力。（§2.4、附录 B.1）

**4. 训练数据**

四个领域拆成五个子集；表中 hard 是保留的评测集，属于全量数据的一部分。（表 1）

| 子集 | 输入 → 答案 | 全量 | hard |
|---|---|---:|---:|
| SARA Numeric | 税法＋个案 → 税额 | 100 | 35 |
| SARA Binary | 税法＋事实＋陈述 → 蕴含/矛盾 | 276 | 30 |
| Airline | 政策＋行程、行李 → 总费用 | 300 | 80 |
| Housing | 州法规＋问题 → yes/no | 5,314 | 78 |
| USCIS-AAO | 规则＋移民上诉事实 → Accepted/Dismissed | 242 | 28 |

前三项复用 SARA、RuleArena；Housing 从原始 6,853 条问答筛选。USCIS 从 2022—2025 年的 6,483 份有效裁决筛至 242 条，两类各 121 条；GPT-5-mini 提取事实并经人工修订、去除结论，标签来自原裁决 Order。Accepted 包括发回重审，不等于申请最终获批。（§2.1–2.3）

hard 的筛法是三种模型各生成两次，**六次中任一次失败**即进入候选，再人工过滤、留出部分：合计 251 条。因此它不是全量数据的随机样本。训练排除 hard；论文未逐阶段披露实际有效训练条数，不能把 6,232 当训练量。（附录 B.2）

后训练基座为 Qwen2.5-32B-Instruct，采用 LoRA，并比较以下阶段及组合：（§4.2、附录 B.5）

- **SFT：**输入规则和个案，目标是参考 Prolog，按 token 学习生成程序。
- **DPO：**同一输入下，参考程序作为 preferred，基座生成的程序作为 rejected；论文未说明后者全部经过错误筛选。
- **Dr. GRPO：**每题采样 5 个程序，执行后按标签给奖励。输出精确匹配得 1；语法或运行错误时，按与参考程序的谓词签名重合度给至多 0.2；超时、缺代码或运行后答错得 0。签名指“名称/参数个数”：交集 2 个、并集 4 个时，奖励为 0.2×2/4＝0.1。

这里学的是程序生成，监督不是置信度标签。

**5. 实验**

主表评测 8 个通用模型，附录另测 3 个代码模型。以下为主表各任务最佳配置，分数范围 0–100，括号是 95% bootstrap 置信区间；不同指标不能直接横比。（表 2）

| 任务 | 模型与配置 | 指标 | 分数（区间） |
|---|---|---|---:|
| SARA Numeric | o3，Zero-shot | Accuracy | 44.4（28.6–60.0） |
| Airline | o3，Few-shot | Accuracy | 90.8（83.8–96.3） |
| SARA Binary | Claude Sonnet 4.5，Direct | Macro-F1 | 70.0（53.0–85.6） |
| USCIS-AAO | GPT-5.1，Direct | Macro-F1 | 71.5（55.1–88.1） |
| Housing | GPT-5.1，Few-shot | Macro-F1 | 46.8（36.0–57.9） |

数值题将输出四舍五入后，允许与 gold 相差 1 美元；分类题对两类分别算 F1 再平均。无法执行或无法解析的输出叫 abstention，计错，**不是模型主动识别风险后拒答**。每题生成 3 或 4 次；bootstrap 每轮重采样个案，并为每个抽中的个案随机抽取一次生成结果，并非多数投票。（§3.2、附录 B.3）

训练改善也不均匀：Airline Few-shot 从基座 15.9（8.8–23.8），到 SFT 53.5（42.5–65.0），再到 SFT→DPO→GRPO 60.4（50.0–71.2）；SARA Numeric 各配置的均值仍低于 10。训练后两组区间重叠，不能仅凭均值认定差异显著。（表 3）

附录表 7 的 GPT-5.2-Codex 在 SARA Numeric Zero-shot 达 45.8（31.5–62.9）；因此 44.4 只是主表最佳值，不能称所有模型的最高分。Housing 此处按表 2 的 46.8 报告，摘要写的是 46.6。

**6. 一条样本全过程**

回到 `s1_a_2_ii_neg`，以下是对官方参考程序的手工追踪，并非本次实测模型日志。[2]

1. **送入模型：**税法文本、Alice 的身份与收入、待验证陈述；gold `0` 留给评测器，不作为待预测答案提供。
2. **形式化事实：**参考程序写入 `surviving_spouse(alice, 2017)` 和 `taxable_income(alice, 2017, 95129)`，并分别定义各税档条件。
3. **执行查询：**检查 `tax_imposed(alice, 2017, section1_a_ii, Tax)`。其中 `95129 =< 89150` 不成立，因此查询失败；正确分支应落入 iii 档，金额相近也不能挽救“按 ii 档”的陈述。
4. **返回与评分：**参考逻辑转入 `Result: Contradiction`，与 gold 一致。这里展示的是参考程序路径，不代表任一被测模型实际生成了它。
5. **训练中的对应形式：**同结构训练样本会把完整参考程序作为 SFT target；DPO 再配一个基座输出；RL 则对新生成代码执行评分。此样本来自官方 smoke，而 smoke 派生自 hard，不能把它直接加入论文的训练集。[3]

**7. Takeaway**

这篇提供了测试“按给定规则办事”的数据和执行接口，也展示了方法的任务依赖性。对本仓库的启发是：评测 harness 时分别记录翻译错误、执行失败和最终答案，另测修复收益与调用成本；这是后续实验建议，不是论文已证明的结果。可靠置信度与选择性转交仍是论文的未来工作。

还需固定数据版本：官方在 2026-05-26 宣布修订存在错误推理、平凡逻辑或硬编码答案的参考程序。因此“执行正确且答案匹配”不足以保证规则忠实。[3] 此外，所核对版本的 `bootstrap_outputs.py` 对各域计算 accuracy，未实现论文声明的分类 Macro-F1；复现分类主表时须核对并补齐该指标。[4]
